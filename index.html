QA CASE STUDY

QA TESTER/SOFTWARE QUALITY ASSURANCE COURSEWORK

Bus Reservation System — Test Case Design & Execution

Assigned as the QA on a team project, I designed and executed 50 structured test cases for a bus reservation system, covering functional flows like user registration and booking.

  • Wrote 50 test cases with prerequisites, test data, step-by-step actions, and expected vs. actual results
  • Tracked outcomes as Pass / Fail / Not Executed for each test run
  • Applied positive and negative test case design to cover edge cases, not just the happy path
  • Coordinated with a Business Analyst for test case review and sign-off
Test Case Design Functional Testing Google Sheets

the problem

Our team needed a dedicated QA role to catch issues before they reached the rest of the group — someone to verify the bus reservation system actually behaved as intended across normal and edge-case inputs, not just the paths a developer tests while building.

my role

As the assigned QA, I reviewed feature requirements, then wrote test cases covering each one — specifying prerequisites, exact test data, expected results, and a place to log actual results and status. I ran each case manually, logged Pass/Fail outcomes, and flagged discrepancies back to the team for fixes, then re-verified after changes were made.

outcome

50 documented test cases across the system's core flows, with a clear audit trail of what was tested, with what data, and what the result was — the same habit of thoroughness I carried into my internship, where it helped me catch errors in client documents before submission.
